Patch Embedding for ECG Signals

How to cut a continuous heartbeat into tokens a transformer can attend to — without losing the waveform's meaning.

signal → segmented patches → linear projection → token sequence [z₁ … z_N] + position → transformer encoder

What patch embedding is

Transformers consume a sequence of tokens, not a raw signal. Patch embedding is the step that turns a continuous ECG trace into that sequence: slice the waveform into short, fixed-length windows ("patches"), then linearly project each window into a fixed-size vector. The idea is borrowed directly from Vision Transformers, which patch an image into 16×16 pixel tiles — here the tile is a short slab of time instead of a slab of pixels.

The payoff is length reduction. A single 10-second, 500 Hz lead is 5,000 samples — far too long for self-attention's quadratic cost. A 25-sample patch turns that into 200 tokens; a 50-sample patch turns it into 100. Each token still carries a recognizable chunk of morphology (part of a QRS complex, a T wave), so the transformer attends over "beats and beat-fragments" rather than individual voltage samples.

The core formula

x ∈ R^(C × T)  // C leads, T time samples
split x into N patches of length L along time  (N = T / L, or via stride S for overlap)
x_i ∈ R^(C × L)  // the i-th raw patch
z_i = W · flatten(x_i) + b  // W ∈ R^(D × C·L), learnable linear projection
z_i = z_i + p_i  // add positional embedding for patch position i Token sequence fed to the encoder: [CLS, z₁, z₂, …, z_N] (CLS optional, task-dependent)

In practice the linear layer is often replaced with a small 1D convolution (kernel = stride = patch length), which is mathematically the same operation but easier to fuse with light local smoothing.

Building the pipeline

  • Preprocess the raw lead(s)
    Resample every record to one common rate (commonly 100–500 Hz), remove baseline wander and powerline noise, and normalize — either z-score per lead over the whole record or per-patch, which is more robust to amplitude drift across a long recording.
  • Choose the patch length and stride
    Pick L in samples (e.g. L = 0.1–0.2s of signal) and a stride S. S = L gives non-overlapping patches (shorter sequence, cheaper); S < L gives overlap, which softens the risk of a patch boundary landing mid-QRS at the cost of a longer sequence.
  • Decide how leads are handled
    Two common patterns: channel-independent — patch each of the 12 leads separately and share the projection weights across leads (keeps sequence per-lead, lets attention mix leads later); or channel-mixed — a patch spans all C leads at once, so a single token already encodes cross-lead morphology at that instant.
  • Linearly project each patch
    Flatten the patch and pass it through the learnable projection (linear layer or strided 1D conv) into the model's embedding dimension D — typically 64–256 for ECG-scale transformers, smaller than typical NLP/ViT dims.
  • Inject position (and lead) information
    Add a learnable or sinusoidal positional embedding per time-index so the model knows patch order — attention alone is permutation-invariant and would otherwise treat the P wave and the T wave as interchangeable. If leads are patched independently, add a lead-identity embedding too.
  • Prepend a [CLS] token (if classifying)
    For record-level tasks — arrhythmia classification, risk scoring — prepend a learnable [CLS] token whose final-layer output feeds the classification head. For per-timepoint tasks (segmentation, beat annotation) skip it and use every output token.
  • Run the transformer encoder
    Standard multi-head self-attention + feed-forward blocks over the patch-token sequence. Attention here is doing the job a CNN's receptive field would do in a 1D-CNN baseline, but globally and adaptively from the first layer.
  • Pretrain with masking (optional, recommended)
    Labeled ECG is scarce. Masked-patch pretraining — hide a subset of patches and train the model to reconstruct them, the ECG analogue of BEiT/MAE — is a common way to get useful representations before fine-tuning on a small labeled set.

Design trade-offs at a glance

ChoiceSmaller / shorterLarger / longer
Patch length LFiner morphology detail, more tokens, higher attention costCheaper sequence, risk of blurring a QRS/P/T wave into one token
Stride vs. lengthNon-overlapping: efficient, but a wave can be split across a boundaryOverlapping: softer boundaries, longer sequence, more compute
Lead handlingChannel-independent: reusable weights, attention learns cross-lead linksChannel-mixed: cross-lead pattern baked into the token itself, less flexible
NormalizationPer-patch: robust to slow amplitude driftPer-record: preserves genuine amplitude differences (e.g. voltage criteria for hypertrophy)

Common pitfalls

Splitting the QRS complex. A poorly chosen patch boundary can cut a QRS spike across two tokens, weakening the very feature most diagnostic tasks depend on. Mitigate with overlap or a patch length safely larger than a typical QRS width (~80–120 ms).
Treating ECG like an image. A 12-lead ECG is not a 2D image — leads aren't spatially continuous the way pixel rows are. Patching across leads naively assumes an ordering/adjacency between leads that isn't physiologically real; channel-independent patching sidesteps this.
Skipping normalization consistency. Train/test amplitude mismatches (different acquisition devices, gain settings) are a common source of silent performance drops — normalize the same way at train and inference time.
No positional signal. Forgetting positional embeddings turns the patch sequence into an unordered set, discarding the temporal order that most rhythm-related diagnoses depend on.

Where this shows up in practice

Patch-based tokenization of physiological time series follows the same recipe as ViT (image patches) and PatchTST (time-series patches). ECG-specific transformers generally reuse this pattern — patch, project, position, attend — layering on masked-patch self-supervised pretraining to cope with limited labeled clinical data, an approach mirrored in ECG-focused work inspired by BEiT/MAE-style masked modeling.
